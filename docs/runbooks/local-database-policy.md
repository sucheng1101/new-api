# Local runtime database policy

## Current decision

The local `5200` runtime uses the existing SQLite database at
`data/one-api.db`. This is the canonical application data source for the
`newapi-dev` Docker project; it is not migrated to the empty MySQL database.

The application container must expose `SQL_DSN=local`, and the runtime lock
must record `database_mode=sqlite` with `database_source` pointing to the
same `data/one-api.db` file.

## Selection rules

1. Run `scripts/local-start.ps1` as the only state-changing entrypoint.
2. A valid existing `data/one-api.db` is preferred and kept in place.
3. A newer validated SQLite snapshot may replace it only when the canonical
   entrypoint records that decision and preserves the previous file.
4. MySQL/PostgreSQL is selected only when the canonical SQLite file is absent
   or invalid and the selected server database contains application data.
5. The runtime lock, container `SQL_DSN`, backup mode, backup source/instance,
   and selected database must agree. A mismatch fails acceptance.
6. Direct `docker compose up`, `restart`, `stop`, `down`, volume deletion, or
   manual DSN switching is outside the workflow.

## Backup gate

Every restart, rebuild, recreate, runtime-mode switch, release, and rollback
must first back up the actual live database used by the running application.
The gate is fail-closed against the database instance actually serving traffic,
not an assumed or previously recorded engine.

For a SQLite runtime, the following fields must all be nonblank and the source
and instance paths must each resolve, from the repository root, to the
canonical live database `root\data\one-api.db`:

- `runtime-lock.database_source`
- `runtime-lock.database_backup.instance`
- `runtime-lock.database_backup.source`
- `database-backup` metadata `source`
- `runtime-lock.database_backup.backup_path`
- `database-backup` metadata `backup_path`

The runtime-lock backup `backup_path` and the metadata `backup_path` must be
independent files that are distinct from the live database; a path equal to
`root\data\one-api.db` is rejected. The runtime-lock `database_mode` is
mandatory and must equal the engine derived from the container `SQL_DSN`.

Missing, blank, or mismatched evidence fails the check before any container is
stopped, rebuilt, recreated, switched, released, or rolled back. Existing
SHA-256, size, validation, engine, MySQL, and PostgreSQL cross-checks remain in
force.

## Verification

After a runtime transition, verify:

- `http://127.0.0.1:5200/api/status` returns `success=true` and the expected
  application settings/data.
- `http://127.0.0.1:5200/api/setup` reports the initialized state.
- `docker inspect new-api-v1.0.6-app` reports `SQL_DSN=local`.
- `.git/new-api-dev/runtime-lock.json` records `database_mode=sqlite`, the
  canonical source path, matching backup evidence, and `acceptance_status=passed`.

Database backup evidence is generated by the runtime gate and remains outside
Git commits. It records the engine, instance/source, timestamp, SHA-256,
validation result, and rollback path.
